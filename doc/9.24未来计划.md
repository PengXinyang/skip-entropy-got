## 9月17日-9月18日：补充结构特征分析

目标：回答“仅凭 token 熵是否还不够，是否需要结构位置、operation 类型、候选得分、后续选择信息”。

需要统计每个 candidate thought：

- `operation`：generate / aggregate / improve
- `operation_index`
- 图深度或相对位置：前期/中期/后期
- predecessor 数量
- successor 数量
- entropy
- score
- 是否被 KeepBestN 选中
- judge `skip_risk`
- judge `usefulness`
- judge `redundancy`

建议形成一个规则判断：

优先跳过：

- judge `skip_risk` 低
- judge `final_answer_contribution` 低
- judge `redundancy` 高
- 没有被后续 KeepBestN 选中
- 同一 operation 下有多个备选 thought，且至少保留一个

谨慎跳过：

- aggregate
- 最终路径上的节点
- 早期拆分节点
- 被后续 KeepBestN 选中的节点
- 承载任务结构字段的节点，例如 keyword_counting 的 `aggr1/aggr2`

这部分不一定必须马上改成新 skip 策略，但汇报时要有清晰证据说明：为什么需要这些特征。

建议主结论：

> 单一步骤 token 熵只能刻画模型生成不确定性，不能直接等价为 GoT 节点重要性。节点是否能跳过，还取决于 operation 类型、结构位置、候选得分、是否进入最终路径，以及它对最终答案的语义贡献。因此第一阶段应从“熵排序”扩展为“熵 + 结构 + judge”的可观测节点重要性分析。

## 风险和应对

| 风险 | 影响 | 应对 |
|---|---|---|
| doc_merge 100 条跑不完 | 主结果不足 | 至少保证 50 条完整，100 条作为持续补充 |
| DeepSeek 限流 | 并行失败 | `parallel-workers` 从 5 降到 3 或 2 |
| judge 成本太高 | 无法全量 judge | 先 judge 20 条，再抽样扩展 |
| entropy 和结果相关性弱 | 原假设受挑战 | 转为强调“熵不是节点重要性，需要结构和 judge” |
| random baseline 更好 | low/high 不占优 | 用它证明单一排序策略存在偏差 |
| doc_merge 无标准答案 | 正确性难评估 | 使用 LLM score、coverage、相似度、失败原因多指标评价 |
